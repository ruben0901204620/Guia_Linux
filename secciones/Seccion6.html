1. Inodos y Dentries

El sistema de ficheros de Linux no guarda archivos de la forma que solemos imaginar de manera convencional. Internamente separa por completo la identidad de un archivo de su nombre utilizando dos estructuras fundamentales: los inodos y los dentries.

// Estructura interna del Layout de Ficheros:

📦 Inodo (inode) 🏷️ Dentry (Directory Entry)
Estructura que almacena los METADATOS de un fichero:
  • Permisos de acceso (rwx)
  • Propietario del archivo (UID de usuario y GID de grupo)
  • Marcas temporales o fechas (creación, modificación, acceso)
  • Tamaño exacto del fichero
  • Número total de enlaces duros (hard links)
  • Punteros a los bloques de datos físicos en el disco
  • ⚠️ NO almacena el nombre del fichero
Cada fichero individual en el sistema mapea a exactamente un único inodo. 		Entrada de directorio que asocia un NOMBRE con un inodo:
  • Nombre explícito asignado al fichero o directorio
  • Número identificador de inodo exacto al que apunta

Un único archivo (un inodo) puede tener múltiples nombres o dentries en el disco. Este mecanismo constituye la base de funcionamiento de los enlaces duros.

Comando

df — Información del sistema de ficheros

Muestra información sobre el uso del almacenamiento global. Al añadir la opción -i, fuerza a la utilidad a listar el estado y consumo de los **inodos** en lugar del espacio métrico en bytes. Es crítico porque un sistema operativo puede quedarse bloqueado por agotar sus inodos disponibles, incluso si cuenta con gigabytes libres de almacenamiento físico.

// Uso sintáctico:
df -i
// Propósito de control:
Ver cuántos inodos están disponibles e identificar saturación en las tablas lógicas.

// Sintaxis operativa:

Muestra una radiografía completa del inodo de un archivo o directorio. Vuelca de forma estructurada parámetros críticos como el tamaño, bloques asignados, permisos en formato octal/carácter, IDs de propietario y el recuento exacto de enlaces lógicos.

2. Enlaces: Simbólicos y Duros

Linux permite crear múltiples nombres o "accesos" para un mismo fichero o directorio[cite: 36]. Existen dos tipos completamente distintos con mecánicas internas totalmente independientes: los enlaces simbólicos (soft links) y los enlaces duros (hard links)[cite: 37].

// Comparación Técnica de Estructuras:

🔗 Enlace Simbólico (soft link) 🗂️ Enlace Duro (hard link)

Apunta al NOMBRE o RUTA del fichero original[cite: 39].

⚠️ Si se borra el original, el enlace queda "roto" (broken symlink)[cite: 39, 43].

✓ Puede apuntar a directorios de forma nativa[cite: 39].

✓ Puede cruzar particiones y sistemas de ficheros diferentes[cite: 39].

Tiene su propio inodo diferente al archivo original[cite: 39].

ls -la muestra explícitamente: nombre -> destino[cite: 39].

Sintaxis: ln -s origen enlace[cite: 39].

Apunta directamente al mismo INODO que el original[cite: 39].

✓ Si se borra el original, el contenido sigue accesible por este enlace[cite: 39, 56].

⚠️ NO puede apuntar a directorios en el sistema[cite: 39].

⚠️ Solo funciona dentro de la misma partición/sistema de ficheros[cite: 39].

Comparte exactamente el mismo número de inodo que el original[cite: 39].

ls -li muestra el mismo identificador numérico en ambos archivos[cite: 39].

Sintaxis: ln origen enlace (sin -s)[cite: 39].
Comando

ln -s — Crear enlace simbólico (soft link)

Crea un acceso directo que apunta de forma lógica hacia el nombre o ruta de un archivo o directorio de destino[cite: 42]. Es la práctica recomendada utilizar rutas **absolutas** al definir el origen para evitar fallos de resolución o enlaces rotos al reubicar el link[cite: 48].

// Sintaxis operativa:
ln -s ruta_origen nombre_enlace [cite: 44]
// Áreas de aplicación:
Enlazar versiones de software, facilitar accesos rápidos a rutas extensas y configurar módulos del sistema[cite: 46].

user@machine : ~ #

// Cómo interpretar un enlace simbólico en la salida de ls -la:

lrwxrwxrwx 1 usuario grupo 35 mayo 20 fich_simbolico -> Escritorio/ficheroDesk.txt [cite: 49]
  • La letra 'l' al inicio de la cadena de atributos identifica formalmente que es un enlace simbólico[cite: 49].
  • Los permisos lrwxrwxrwx pertenecen de forma virtual al enlace; las restricciones reales aplicadas serán las del archivo destino[cite: 49].
  • El número 35 refleja el tamaño en bytes del texto explícito de la ruta destino a la que está apuntando[cite: 49].
  • Hacer lectura con comandos como cat sobre el enlace leerá el contenido del fichero original transparentemente[cite: 49].

Comportamiento por distribución:

Debian / Ubuntu Arch Linux Fedora
$ ln -s /var/log acceso_logs $ ls -la Muestra la flecha apuntando hacia el destino en el listado extendido[cite: 48]. $ ln -s /home/usuario/archivo.txt enlace $ ls -la Mismo comportamiento en Arch. Los enlaces se visualizan resaltados en color cian por defecto[cite: 48]. $ ln -s /home/usuario/archivo.txt enlace $ ls -la Identificadores idénticos en Fedora[cite: 48].
Comando

ln — Crear enlace duro (hard link)

Crea un segundo nombre mapeado en las tablas lógicas que apunta de manera directa hacia el **mismo número de inodo** del archivo original[cite: 52]. Ambos nombres operan con idéntica prioridad para el sistema operativo; los datos físicos del archivo solo se eliminarán de los bloques de disco cuando la totalidad de los enlaces duros asociados hayan sido borrados[cite: 53, 57].

// Sintaxis operativa:
ln fichero_origen nombre_enlace [cite: 54]
// Mecanismo del contador:
El contador de enlaces reflejado en la segunda columna de ls -l incrementa su valor de forma automática al crear enlaces duros[cite: 59].
tty_register // simulate --ln-hard
user@machine : ~ #

// 📂 ¿Por qué los directorios tienen al menos 2 hard links? [cite: 60]

Todo directorio nuevo inicializa con **2 enlaces duros** automáticamente por diseño de sistema[cite: 60]:

  1. Su propia entrada nominal dentro de la carpeta padre[cite: 60].
  2. El enlace interno autorreferencial conocido como punto "."[cite: 60].

Al añadir subcarpetas anidadas, el contador del directorio padre incrementa: cada subdirectorio incorpora un puntero ".." que apunta de vuelta al padre[cite: 60].

Comportamiento por distribución:

Debian / Ubuntu Arch Linux Fedora
$ ln archivo.txt enlace_duro $ ls -li Permite verificar la asignación del mismo número de inodo exacto en ambos lados[cite: 59]. $ ln archivo.txt enlace_duro $ ls -li Comportamiento idéntico en Arch[cite: 59]. $ ln archivo.txt enlace_duro $ ls -li Comportamiento idéntico en Fedora[cite: 59].

3. Wildcards (Comodines)

Los wildcards (comodines) son caracteres especiales que la shell interpreta **ANTES** de ejecutar cualquier comando. La shell se encarga de sustituirlos de forma transparente por los nombres de los ficheros que coincidan exactamente con el patrón indicado. Es fundamental comprender que no son una función de los comandos individuales, sino una característica nativa de la propia shell.

// Sintaxis y Patrones de Comodines Disponibles:

🔣 Opción / Patrón 📝 Descripción Funcional
* Coincide con CUALQUIER cadena de caracteres (incluyendo una cadena vacía). Es el wildcard más utilizado en la shell.
? Coincide exactamente con UN solo carácter cualquiera.
[abc] Coincide con cualquiera de los caracteres listados explícitamente entre los corchetes (a, b o c).
[!abc] Coincide con cualquier carácter que NO sea ninguno de los listados en el grupo.
[a-z] Coincide con cualquier carácter que se encuentre dentro del rango alfabético de la "a" a la "z".
[[:digit:]] Clase POSIX: Coincide con cualquier dígito numérico en el rango del 0 al 9.
[[:alpha:]] Clase POSIX: Coincide con cualquier letra (tanto minúsculas como mayúsculas: a-z, A-Z).
[[:alnum:]] Clase POSIX: Coincide con cualquier carácter alfanumérico (cualquier letra o dígito).
[[:upper:]] Clase POSIX: Coincide exclusivamente con cualquier letra en mayúscula.
[[:lower:]] Clase POSIX: Coincide exclusivamente con cualquier letra en minúscula.
[[:space:]] Clase POSIX: Coincide con espacios en blanco, tabuladores y saltos de línea.

// ⚙️ Atención: La shell expande primero, el comando recibe el resultado

Cuando escribes un comando como $ cat fichero*, la shell busca de manera autónoma todos los archivos del directorio actual que coincidan con el patrón. Si localiza fichero1.txt, fichero2.txt y ficheroC.txt, reconstruye la línea de comandos antes de invocar el binario, enviando exactamente:

cat fichero1.txt fichero2.txt ficheroC.txt

Si ningún fichero coincide con el patrón en bash, la shell pasa por defecto el wildcard literal como argumento al comando. En zsh, el comportamiento predeterminado producirá un error inmediato bloqueando la ejecución si no hay coincidencias.

Uso Común

Utiliza el comodín asterisco para leer o procesar de golpe todos los archivos cuyos nombres comiencen con una cadena específica, sin importar los caracteres que sigan o la longitud de su nombre.

Uso Común

Fuerza la coincidencia de nombres donde exista exactamente un único carácter variable en la posición del signo de interrogación.

user@machine : ~ #
Uso Común

Lista únicamente los directorios o archivos que inicien formalmente con una letra mayúscula utilizando las clases estandarizadas POSIX.

Comportamiento por distribución:

$ cat fichero* $ cat fichero?.txt $ ls -d D* Los wildcards funcionan de manera idéntica en todas las distribuciones ya que son procesados por la shell Bash. $ ls *.conf $ ls fichero?.txt $ ls [[:upper:]]* Mismo comportamiento en Arch. Si se utiliza la shell Zsh, los comodines pueden presentar ligeras variaciones de control si no hay coincidencias en el disco. $ ls *.conf $ ls fichero?.txt $ ls [[:upper:]]* Comportamiento completamente idéntico en Fedora bajo la shell estándar Bash.

4. Expansiones de la Shell (Shell Expansions)

Las expansiones son transformaciones que la shell realiza en la línea de comandos antes de ejecutarlos. Existen varios tipos:

Comando

echo — Mostrar texto en pantalla

Muestra texto o el resultado de expresiones en la terminal. Es un builtin de bash y también existe como programa externo. Es la herramienta principal para probar las expansiones de la shell.

// Uso sintáctico:
echo [opciones] [texto o expresión]
// Para qué sirve:
Mostrar texto, variables, resultados de operaciones y expansiones. Muy usado en scripts para imprimir mensajes y depurar.

user@machine : ~ #

// Opciones de echo:

Opción / Patrón Descripción
-e Habilita la interpretación de secuencias de escape (\n, \t, \a, etc.).
-n No imprime el salto de línea final.
-E Desactiva la interpretación de secuencias de escape (por defecto).

Ejemplos de control general por distribución:

Debian / Ubuntu Arch Linux Fedora
$ echo esto es un texto $ echo $((2 + 2)) echo es un builtin. Verifica con: type echo. $ echo hola mundo $ echo {A..Z} Idéntico en Arch. En zsh puede comportarse diferente con algunos wildcards. $ echo hola mundo $ echo {A..Z} Idéntico en Fedora.

📦 Expansión de Ruta (Pathname Expansion)

5. Sustitución de Comandos (Command Substitution)

La sustitución de comandos permite usar la **SALIDA** de un comando como argumento de otro. La shell ejecuta el comando interno y reemplaza la expresión por su resultado automáticamente en la línea de ejecución.

// Comparación de Métodos de Sustitución:

Sintaxis moderna: $(comando) Sintaxis clásica: `comando`
$ ls -la $(which cat) $ echo $(python3 -c 'print("hola")') $ echo $(ls)

✓ Recomendada: Es altamente legible y permite el anidamiento directo de comandos.

echo "la ruta es: $(which cat)" 		$ ls -la `which cat` $ echo `python3 -c 'print("hola")'` $ echo `ls`

⚠️ Antigua: Es propensa a confusiones visuales y resulta difícil de anidar y leer.

echo "la ruta es: `which cat`"
Mecanismo

$() y ` ` — Ejecución e Inyección

Sustituye la expresión evaluada por la salida estándar del comando ejecutado. Su propósito fundamental radica en capturar dinámicamente el resultado de un comando secundario para transferirlo directamente como argumento de un comando principal.

// Sintaxis operativa:
comando1 $(comando2)
comando1 `comando2`
// Caso de aplicación práctica:
Encontrar de forma dinámica la ruta exacta del binario cat y pasársela a ls para validar sus metadatos detallados.
tty_register // simulate --SHELL-substitution
user@machine : ~ #

// Casos prácticos de command substitution:

$ ls -la $(which cat) # Ver detalles del ejecutable cat.
$ ls -la $(which python3) # Ver dónde está instalado python3.
$ echo $(python3 -c 'print("hola mundo")') # Ejecutar Python desde bash de forma integrada.
$ cat fichero$(( 1+1 )).txt # Abrir fichero2.txt combinando aritmética en la misma instrucción.

Nota: $(which cat) con un comando interno mal escrito producirá un error controlado del subproceso interno, pero bash continuará la ejecución global de la línea.

Comportamiento por distribución:

Debian / Ubuntu Arch Linux Fedora
$ ls -la $(which cat) $ ls -la `which cat` $ echo $(ls) $(which cat) ejecuta internamente el comando, obtiene la cadena /bin/cat, e inmediatamente ls -la recibe y opera sobre esa ruta. $ ls -la $(which bash) $ echo $(uname -r) Comportamiento idéntico en Arch Linux. $ ls -la $(which bash) $ echo $(uname -r) Comportamiento idéntico en Fedora.

6. Comillas en la Shell de Linux

Las comillas controlan el nivel de **interpretación** o expansión que la shell aplica a los caracteres especiales dentro de una cadena de texto. Existen tres tipos de entrecomillado con comportamientos totalmente opuestos:

// Tipos de Comillas y su Mecánica de Escape:

Comillas Dobles (") Comillas Simples (') Invertida / Escape (\)
Expansión Parcial (Weak Quoting):

Protege la mayoría de caracteres especiales, pero **PERMITE** expandir:

  • Variables ($VAR)
  • Sustituciones ($(SHELL))
  • Aritmética ($((op)))

Evita la expansión de rutas con wildcards como * y ?.

 Literal Absoluto (Strong Quoting):

Protege **TODOS** los caracteres especiales de manera estricta.

Todo lo que esté dentro se convierte en texto plano literal.

No se expanden variables, ni comandos, ni operaciones.

Ideal para pasar cadenas íntegras a lenguajes como Python o AWK desde la terminal. 		Escape de Carácter Único:

Invalida el significado especial únicamente del **SIGUIENTE** carácter inmediato.

Permite usar espacios, signos de dólar o comillas dentro de textos sin romper la sintaxis.

Equivale a envolver un solo carácter entre comillas simples.
Uso Común

echo "..." — Entrecomillado doble con expansión

Permite imprimir textos compuestos manteniendo intactos los espacios múltiples, pero dándole libertad a la shell para inyectar los valores dinámicos de las variables de entorno o sustituciones de comandos.

Uso Común

echo '...' — Entrecomillado simple literal

Anula de forma masiva cualquier superpoder que tengan los caracteres dentro de la cadena. Es la herramienta mandatoria cuando necesitas documentar o imprimir sintaxis de código de forma cruda sin interferencias de la shell.

user@machine : ~ #
Uso Común

Permite neutralizar un único carácter especial en una posición exacta sin necesidad de abrir o cerrar bloques completos de comillas en la línea de comandos.

7. Escapando Caracteres Especiales

La barra invertida (\) es el carácter de escape de la shell[cite: 122]. Colocado antes de un carácter especial, le quita su significado especial y lo trata como un literal[cite: 123].

Comando

\carácter — Carácter de escape

La barra invertida escapa el siguiente carácter: lo convierte en un carácter literal sin significado especial para la shell[cite: 126]. Es equivalente a encerrar ese único carácter entre comillas simples[cite: 127].

// Uso sintáctico:
\carácter_especial [cite: 128]
// Para qué sirve:
Usar caracteres especiales como literales: espacios en nombres de ficheros, asteriscos literales, signos de dólar, etc[cite: 129].
tty_register // simulate --backslash-escape
user@machine : ~ #
Debian / Ubuntu Arch Linux Fedora

Comando

echo -e — Secuencias de escape interpretadas

Con la opción -e, echo interpreta las secuencias de escape especiales dentro de las comillas dobles[cite: 134]. Sin -e estas secuencias se imprimen como texto literal[cite: 135].

// Uso sintáctico:
